`sos adopt` does **not** overwrite `hooks/pre-commit` — it lists it under
`REVIEW / merge by hand (existing-or-missing — adopt did NOT touch)` and

backstop-minimal hook stays the ACTIVE hook** (opposite winner vs forward
order, where Claude's dev `[8/8]` hook stays active because it's rendered
first and Codex's later install detects differing content and backs off).
`core.hooksPath` unchanged (`hooks`), still executable. `.codex/`, `.agents/`,
`AGENTS.md`, `.sos-state/` all intact after adopt. This is the documented
non-clobber contract working correctly, just producing an order-dependent
"who owns hooks/pre-commit" outcome — worth a one-line doc note (which hook
wins depends on install order) but not a bug.

commit. Reproducible: `git branch --show-current` prints `main`, but
`git show-ref --verify --quiet refs/heads/main` fails pre-first-commit. This
is pre-existing (not caused by dual-runtime), but the A4 test matrix
surfaced it. Recommend a small P080x note (not urgent — narrow window,
first-commit-only).

## Task 4 — Nhóm D: regression P079 round-5 + sync/map dual smoke

### D1. Backstop fail-CLOSED (missing `block-env-commit.sh`) — **FAIL (HIGH)**

```text
$ mv scripts/block-env-commit.sh /tmp/...bak
$ echo 'SECRET=xxx' > .env && git add -f .env
$ git commit -m "d1 test"
[7/8] Block .env* commit
  ⏭  scripts/block-env-commit.sh missing — run scripts/install-hooks.sh after bootstrap
EXIT=1   <- only blocked because [8/8] trust-gate coincidentally flagged the
            FILE REMOVAL itself as a baseline-diff (unrelated to .env content)
```

Proved the coincidence by removing the confound (rebaseline BEFORE
committing, so trust-gate sees no drift):

```text
$ mv scripts/block-env-commit.sh /tmp/...bak2
$ git add -A && scripts/trust-gate.sh rebaseline && git add .sos-trust-baseline
$ echo 'SECRET=xxx' > .env && git add -f .env
$ git commit -m "d1 bypass test — proves fail-open gap"
[7/8] Block .env* commit
  ⏭  scripts/block-env-commit.sh missing — run scripts/install-hooks.sh after bootstrap
[8/8] Trust gate ... ✅ Auto-exec surfaces match baseline; no hidden unicode
⚠️  1 warning(s). Commit allowed.
[main 183b42c] d1 bypass test — proves fail-open gap
 3 files changed, 1 insertion(+), 55 deletions(-)
 create mode 100644 .env
 delete mode 100755 scripts/block-env-commit.sh
EXIT=0   -- .env WITH a fake secret committed cleanly.
```

Root cause (`hooks/pre-commit` dev `[8/8]` hook, phases `[6/8]` and `[7/8]`):
both wrap their guard-script call in `if [ -f script ]; then ... else echo
"⏭ missing"; fi` — the `else` branch does NOT increment `FAIL_COUNT`, so a
missing guard script silently downgrades to "allowed." This is the EXACT
"round-4 A3/A4" bug the Codex-side backstop-minimal hook's own header
comment (`hooks/pre-commit` rendered by `sos install --runtime codex`,
confirmed fail-closed — see D2) says was fixed. The fix was applied to the
backstop-minimal hook only; the dev `[8/8]` hook (rendered by `sos new`,
Claude path) still has the old fail-open branches. **This is a genuine
regression/inconsistency between the two runtimes' hook variants — the
Claude-rendered hook is LESS safe than the Codex-rendered one for the same
2 invariants.** Recommend P080x (Tầng 1, Debate) to port the backstop's
fail-closed pattern into `hooks/pre-commit`'s own `[6/8]`/`[7/8]` phases.
