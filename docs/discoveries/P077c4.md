## Rust `adopt.rs` deviations from Bash (documented, all intentional)

- **`.mcp.json`/`.claude/settings.local.json` exists-branch (jq-merge)** — implemented by shelling out to the real `jq` binary (same as Bash, no new JSON-merge crate dependency added), but NOT exercised by the parity fixture (Constraint 7 — the fixture's brownfield target never seeds either file, so it always takes the create-if-absent branch). Implemented for real-world correctness only; out of hard-fail parity scope.
- **map-within-adopt via subprocess re-invocation** — `run_map_subcommand()` calls `std::env::current_exe()` and re-invokes the SAME compiled `sos` binary as `sos map <target>`, output fully discarded. This reuses `map.rs`'s logic WITHOUT modifying `map.rs` (phiếu constraint: "Files KHÔNG sửa" lists `map.rs`) while still matching Bash's `sos_map "$target" >/dev/null` output-suppression semantics. Functionally equivalent to Bash's in-process function call + stdout redirect; the only observable difference (a nested process spawn) is invisible to the parity fixture, since only the WRITTEN FILE and (absence of) stdout output are checked.
- **Non-clobber list order** — `added`/`conflicts` preserve raw `WalkDir` enumeration order (not sorted), matching Bash's unsorted `find -L` — same divergence class as `sync.rs`'s spine walk (documented there, reused here).
