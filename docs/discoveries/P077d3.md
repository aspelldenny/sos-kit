## Assumptions in phiếu — adapted (Tầng-2 self-decided, no escalation)

- **`resolve_tools()` signature changed from `Vec<String>` to `Result<Vec<ToolStatus>>`.** The d2 stub returned an unused, meaningless `Vec<String>`; to actually gate a required-tool failure (Task 5's explicit requirement — "required missing/older → install FAIL rõ"), the function needed to be fallible. This is an internal engine function's own signature (not a trait/schema/CLI-surface change per the DOCS GATE table), same class of Tầng-2 evolution as d2's own `Decision::NoOp` 4th-variant addition (self-decided, logged in that phiếu's own Discovery). Caller (`commands/install.rs`) updated from `let _ = engine::resolve_tools();` to `engine::resolve_tools()?;` — since this now runs BEFORE `decide_targets()`/`apply()` (same call position d2 wired), a required-tool failure aborts before any filesystem mutation happens, which trivially satisfies "fail rõ + rollback" without any new rollback machinery.
- **Manifest-path resolution: embed via `include_str!`, not `SOS_KIT_DIR` env var or a `--manifest` flag.** The phiếu explicitly left this `[needs Worker verify]`. Reasoning for the choice: the compiled `sos` binary is meant to run INSIDE arbitrary target projects that do not necessarily have a sos-kit checkout available at runtime (that's the whole point of a distributed CLI) — an env-var/flag scheme would require every user to point at a local sos-kit clone, which is exactly the kind of friction OA-07's "reproducible version selection" goal wants to eliminate. Embedding pins the manifest data to the specific compiled binary, guaranteeing the pin travels with the tool. Test fixtures bypass this entirely (they construct synthetic `ToolManifest` values directly via `parse_manifest()`, never touching the embedded constant), so this choice doesn't block testability.
- **Version comparator is a hand-rolled dotted-tuple compare, not pure exact-string equality.** See anchor #8 above — this is strictly more useful (accurate Newer/Drift split) while adding zero new dependency, staying inside the phiếu's own guardrail ("no `semver` crate").
- **`gate_required()` extracted as a shared core function** (used by both `engine::resolve_tools()` and directly testable in `tools.rs` tests) rather than duplicating the "resolve → check required → bail" logic inline in `engine.rs`. This is exactly the phiếu's own "một cơ chế, hai/ba surface" mandate (Task 2/Constraint 2) taken one function further — internal code organization, not a schema/API change.
