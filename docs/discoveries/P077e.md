# Discovery — P077e (CUTOVER: Rust `sos` canonical for 6 heavy subcommands)

## Anchor #2 reconcile (11 vs 13) — the critical finding

`bin/sos.sh`'s dispatch `case` block had **11 named subcommand arms** (not 13): `new`,
`adopt`, `sync`, `map`, `init`, `blueprint`, `contract`, `apply`, `recipe`, `launch`, `status`
(+ `help|--help|-h` and a catch-all `*)`). Grep (`grep -n "^sos_install\|^sos_tools"`) confirmed
**zero** existing Bash function or dispatch arm for `install`/`tools` anywhere in the file —
they are brand-new commands, Rust-only (P077d2/P077d3), no prior Bash counterpart to flip.

So the "6 heavy" set decomposed as: **4 arms flipped** (`new`/`adopt`/`sync`/`map` — previously
routed to `sos_<cmd>` Bash functions, now `exec` the Rust binary) + **2 arms added new**
(`install`/`tools` — never existed in the dispatcher before this phiếu). The phiếu's own Task 2
note anticipated exactly this scenario ("nếu chưa có arm → thêm arm mới, không phải flip arm
cũ") — Worker executed that branch, no escalation needed.

## Anchor #5 — recursion defense mechanism

`install.sh:151-158` confirmed the launcher installs itself literally as `sos` on the user's
PATH (`printf 'SOS_KIT_DIR="%s" exec bash "%s/bin/sos.sh" "$@"\n' ... > "$BIN_DIR/sos"`). The
resolver (`_sos_rust_bin` in `bin/sos.sh`) therefore never calls `command -v sos` — only
`SOS_RUST_BIN` env override, explicit build-dir candidate paths
(`$CARGO_TARGET_DIR/{release,debug}/sos`, `<workspace>/target/{release,debug}/sos`), and an
on-demand `cargo build --bin sos` fallback. Verified live: `grep -n "command -v sos" bin/sos.sh`
only matches the explanatory comment, never an executed call.

## Fail-LOUD verification
- First attempt (`SOS_RUST_BIN=/nonexistent CARGO_TARGET_DIR=/tmp/nonexistent-target`, cargo
  still on PATH) unexpectedly SUCCEEDED — this was a **test-design gap, not a resolver bug**:
  `cargo build` respects `CARGO_TARGET_DIR` and will happily build a fresh binary there, so the
  build-on-demand step self-healed. Corrected test: stripped `~/.cargo/bin` from PATH (so `cargo`
  itself is unavailable) + invalid `SOS_RUST_BIN` + fake `CARGO_TARGET_DIR` → dispatcher printed
  the exact fail-LOUD message (`sos: Rust binary 'sos' not found — cutover requires it (P077e).`)
  and returned exit 127, with **no target directory created** (proof the dormant Bash `sos_new`
  never ran).
