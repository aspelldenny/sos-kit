## Rust `map.rs` deviations from Bash (documented, all intentional bug-for-bug matches)

- No deviations in observable output (stdout + file byte-identical, verified above).
- Implementation-level note: the Rust scanner treats `-path '*/X/*'` as a plain substring match on the full path string (same semantics `find`'s glob achieves for this fixture shape); it does not special-case the edge case where the fixture's target directory itself is literally named e.g. `migrations` (Bash's `find` would include the root in its traversal and, for that one edge case, `sed`'s prefix-strip would leave the full absolute path unstripped in output — a corner-case Bash quirk). This edge case does not occur in `map.golden`'s fixture and is out of scope for c1 (bug-for-bug parity is scoped to the frozen fixture's observable behavior, verified bit-exact); flagging here for completeness in case a future fixture ever names its target root after one of the dir-match surfaces.

## Per-command flip mechanism + two-fixture pattern (for c2/c3/c4 reuse)

- `HARD_FAIL: bool` → `const PARITY_ENFORCED: &[&str] = &["map"];`. `parity_skeleton_informational` skips any command already in the set (handled by its own dedicated test instead) and stays informational for the rest.
- `map` gets its own `#[test] fn parity_map_enforced()` — builds the fixture, runs the Rust binary, asserts stdout vs `map.golden` AND file-content vs `map.agent_map.golden`, hard-fail on either.
- Two-fixture pattern for future commands whose real work-product is a file: (1) extend `capture.sh`'s freeze branch additively to `cat` + normalize the written file into a new `<cmd>.<artifact>.golden`; (2) add a dedicated enforced test that asserts both stdout and file content; (3) add the command's name to `PARITY_ENFORCED`. Feed-forward note added to `docs/plans/P077c-decomposition.md` flagging c3 (`new`)/c4 (`adopt`) to CHECK (not assume) whether they need this same second fixture, since both also write files as their real product.
