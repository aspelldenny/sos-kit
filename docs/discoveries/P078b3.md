# P078b3 Discovery Report — Codex adapter enforcement (7 artifacts, P078b DONE)

## Anchor #1 (CRITICAL) — apply_patch marker syntax

Report (`docs/adapters/CODEX_ADAPTER_DISCOVERY_2026-07-22.md:13`) named the envelope
(`tool_name="apply_patch"`, patch text in `tool_input.command`) but not the marker syntax
inside the patch body. Worker CHALLENGE (Turn 1) escalated rather than guess — a plausible
training-data prior (OpenAI's public V4A format) existed but had no SOUND oracle in-session.

**Resolved via live probe (Debate Log Turn 2):** Sếp ran Codex CLI (gpt-5.6) and captured 4
real `PreToolUse` hook stdin payloads, saved at
`crates/sos-adapter-codex/tests/fixtures/codex-apply-patch-payloads.jsonl`. Confirmed exactly
the V4A envelope the prior guessed: `*** Begin Patch\n*** Add|Update|Delete File: <path>\n...
*** End Patch`, with the patch body's newlines escaped as literal `\n` inside the JSON string
(not real newlines). Extraction regex verified directly against all 3 real apply_patch fixture
lines before writing any guard code:
```
grep -oE '\*\*\* (Add|Update|Delete|Move) File: [^\\"]+' | head -n1 | sed -E 's/^\*\*\* (Add|Update|Delete|Move) File: //'
```
Fail-open risk is now closed: every guard's extraction pipeline is wrapped with `|| true` so
`set -euo pipefail` does not abort the script on a no-match `grep` (a genuine bug caught during
implementation — see "Bugs found and fixed" below); an empty extraction result always routes to
an explicit fail-CLOSED branch (`exit 2`), never falls through to allow.

## fail-CLOSED — branches inverted vs Claude

Every guard that parses `apply_patch` (architect-guard, orchestrator-guard, block-env-edit,
approval-gate) BLOCKs (exit 2) when the `*** Add/Update/Delete/Move File:` extraction yields no
path — this is the deliberate inversion of the Claude precedent (`architect-guard.sh:51-52`
"don't block on weird input"). Rationale documented in each guard's header comment and in
`adapters/codex/CAPABILITY.md`'s new "fail-CLOSED design note" subsection: Claude's `file_path`
payload is reliably typed/parseable, so unparseable input essentially never occurs in practice;
Codex's `apply_patch` patch-body parsing is inherently more fragile (free-text pattern match),
so an unparsed patch silently allowed through would be a real bypass, not a theoretical one.

## Approval-gate (E5) — state-file path/format

No prior convention existed in this codebase for a machine-readable ticket-state projection
(`core/STATE.md` deliberately leaves the concrete file/format integration-defined). Chose
`.sos-state/ticket-state.env` — plain `key=value` lines (`version=`, `approved_version=`),
consistent with the existing `.sos-state/<role>-active` marker-file convention already used by
Claude guards. Guard reads only, never writes `approved_version` (mutation authority stays
owner/bounded-delegate per `core/STATE.md`). Missing state file or version mismatch → BLOCK
(fail-CLOSED); editing the ticket file itself (`docs/ticket/P<NNN>-*.md`) is always allowed
through this guard regardless of state (drafting/amending a ticket doesn't need its own prior
approval).

## Bugs found and fixed during implementation (worth flagging for future guard authors)

1. **`set -euo pipefail` + no-match `grep` in a command substitution aborts the script with
   the WRONG exit code** (grep's exit 1, not the guard's intended exit 2) instead of reaching
   the fail-CLOSED branch. Fixed by appending `|| true` inside every `PATCH_PATH=$(...)`
   pipeline so the assignment always succeeds and an empty `PATCH_PATH` is handled explicitly.
2. **Initial design cd'd into the payload's `cwd` JSON field before falling back to
   `git rev-parse`.** This is speculative behavior beyond what the ground-truth sample confirms
   (it only proves the field exists, not that a hook subprocess's actual working directory
   differs from it). It also broke local mock-payload testing directly: the real captured
   fixture's `cwd` value (`/tmp/codex-hook-capture.Ur7gwW`) happened to still exist as a stale
   directory on the dev machine from Sếp's earlier probe session, so the guard silently
   relocated into that unrelated directory and lost the test's `.sos-state/` marker. Removed
   the cd-into-cwd step entirely; guards now just resolve `git rev-parse --show-toplevel`
   (falling back to the process's actual cwd) — simpler and avoids trusting an unconfirmed
   relocation behavior.
