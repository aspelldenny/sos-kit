## Implementation choice: single-point fix for BUG 2 (per Debate Log Turn 1 Tầng-2 note)

Debate Log Turn 1 flagged that `hash_file()` (`trust-gate.sh:88-95`) is the single wrapper both the generate branch (`:190`) and compare branch (`:227`) call, and normalizing *inside* `hash_file()` would transparently also fix the 3rd NF-read site (`:242`, `baseline_paths` for `comm` added/removed detection) — since a baseline written via a fixed `hash_file()` never contains `*` in the first place. Took that option: piped `hash_file`'s output through `awk '{ h=$1; sub(/^\*/, "", $2); print h"  "$2 }'` inside the wrapper itself, rather than duplicating the normalization at both the generate and compare call sites as Task 5's literal two-branch instruction suggested. Both are correct per the phiếu ("either way anchor #7's 3rd site is covered, not a gap requiring phiếu change") — picked the DRY-er option.

## `display_out_path()` helper — why not a blanket `.replace('\\', "/")` on `out.display()`

First implementation attempt (blanket-normalize the whole `out.display()` string) broke `parity_map_enforced`'s stdout assertion differently: the parity test harness does `raw.replace(target_str, "<TARGET>")` where `target_str` is the literal CLI arg (native separators on Windows, e.g. `C:\Users\...\map-fixture`). If the whole display path is forward-slash-normalized first, `target_str` (with backslashes) no longer appears as a substring, so the harness's replace is a no-op and the raw absolute path leaks into the assertion, mismatching the golden's `<TARGET>/docs/AGENT_MAP.yaml`. Fixed by adding `display_out_path(target, out)` which strips the (forward-slash-normalized) `target` prefix from the (forward-slash-normalized) output path, then re-prepends the ORIGINAL `target` string byte-for-byte before appending the forward-slash suffix — preserving the substring the test harness's `<TARGET>` substitution depends on while still forcing `/` after it.

## Edge cases / limitations found

- `is_noise()`'s signature stayed `&str` (unchanged) — normalization happens at both call sites instead, per Task 2's own fallback guidance. This means any FUTURE caller of `is_noise()` must remember to normalize before calling; not enforced by the type system. Noted here for future maintainers (this is exactly the kind of thing Discovery Report exists to surface).
- `hash_file()`'s awk-based field split (`$1`/`$2`) assumes no whitespace in file paths — true for every entry in `SURFACE_GLOBS` today (all repo-relative kit paths), consistent with the pre-existing `awk '{print $NF}'` compare-path logic already making the same assumption.
