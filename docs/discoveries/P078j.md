## Cơ chế canonicalize chọn (bắt buộc)

**Portable primitive: resolve DIRNAME only, re-append basename** — `RESOLVED_DIR=$(cd
"$CAND_DIR" 2>/dev/null && pwd -P) || true`; `CANON_PATH="$RESOLVED_DIR/$CAND_BASE"` if
`RESOLVED_DIR` non-empty, else fall through to the raw path unchanged. Applied identically to
`REPO_ROOT` itself (`REPO_ROOT=$(pwd -P 2>/dev/null || printf '%s' "$REPO_ROOT")`, run right
after the existing `cd "$REPO_ROOT"`).

**Rationale:**
- **macOS-BSD-vs-GNU:** `man realpath` on macOS confirmed (per the phiếu's Final consensus, and
  re-confirmed by reading the guard bash's comments) that BSD `realpath`/`readlink` lack `-m`/`-e`/`-s`/`-f`.
  `cd ... && pwd -P` is POSIX (`pwd -P` is required by POSIX.1-2008) and behaves identically on
  both macOS and GNU/Linux — no feature-detection needed.
- **Target-not-exist-safe:** resolving only the DIRNAME (never the full candidate path) means a
  file that does not yet exist on disk (bootstrap-create, P078d2a #5/B1) still canonicalizes
  correctly, because only the directory needs to exist, and it always does for a real write target.
- **`|| true` under `set -e`:** discovered mid-implementation (see below) — the `cd ... && pwd -P`
  command substitution is a plain assignment statement; under `set -euo pipefail`, if the dirname
  doesn't exist, `cd` fails and the FULL SCRIPT would abort right there (not merely fall through to
  the intended conservative fallback). Fixed by appending `|| true` to the assignment. This was
  caught by the Task-2 tests themselves (multi-path bundle test with a non-existent `src/` dir
  failed with exit code 1 — a script-abort code, not `0`/`2` — instead of the expected `2`).

## 2-chiều fix note

Gap B has two distinct, opposite-direction consequences (round-4 §B4):
1. **Marked-actor advance leak** — worker/architect marker present, an already-approved state
   (`V3/V3`) advances to `V4/V4` via an alias path (`/tmp/...`) without the early-BLOCK firing,
   because the pre-fix lexical strip never matched the alias against canonical `REPO_ROOT`.
2. **Main-thread false-block** — no marker present, a legitimate approval write via the same alias
   path never wins the state-file-alone exemption for the identical reason, and is wrongly BLOCKed.

Canonicalize fixes BOTH simultaneously because it operates on the SAME normalize site both
consumers (exemption + early-BLOCK) share — proven by `approval_gate_symlink_alias_marked_actor_advance_blocks`
(direction 1, BLOCK) and `approval_gate_symlink_alias_main_thread_approval_allows` (direction 2, ALLOW).

## Fail-closed note

`approval_gate_path_trick_outside_repo_root_stays_fail_closed` (new): a candidate path that
canonicalizes to a directory entirely OUTSIDE `REPO_ROOT` (no shared canonical prefix, even after
resolution) never wins the state-file-alone exemption — it falls through to the normal fail-CLOSED
`STATE_FILE` existence check (BLOCK, since no state file exists under the guard's own repo root).
The `../`-containing-after-strip belt-and-braces check from P078h (`case "$NORM_PATH" in *..*)`)
is left untouched and still applies as a second layer.

## Symlink test helper

Added `run_guard_symlink()` (`crates/sos-adapter-codex/src/lib.rs`, next to `run_guard_dynamic`):
creates a REAL temp directory and a SEPARATE symlink (`std::os::unix::fs::symlink`) pointing at
it, spawns the guard with its working directory bound to the REAL dir (so `REPO_ROOT` resolves
canonically, exactly as `git rev-parse --show-toplevel`/`pwd -P` would in production), and lets
the caller build the `apply_patch` payload using the ALIAS (symlink) path. This reproduces the
exact real/alias split round-4 found (macOS `/tmp` → `/private/tmp`) without depending on any
OS-specific mount, so it runs identically on CI Linux (which has no pre-existing `/tmp` symlink) —
the symlink is constructed fresh inside the test's own temp dir every run.
