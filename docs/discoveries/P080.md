1. **D1 — HIGH, real regression/inconsistency (see findings doc for full repro):** the dev `[8/8]` `hooks/pre-commit` (rendered only by `sos new`, Claude path) is fail-OPEN on its `[6/8]` no-code-on-default and `[7/8]` block-env-commit phases when the delegated guard script is missing (`else: echo "⏭ missing"` with no `FAIL_COUNT` increment). This is the exact "round-4 A3/A4" bug that P078i's own header comment (backstop-minimal hook, Codex path) says was fixed — but the fix only landed in the Codex-rendered backstop hook, never ported back to the Claude-rendered dev hook. Proved live: removed `scripts/block-env-commit.sh`, rebaselined trust-gate (removing the confound of the unrelated baseline-diff catch), committed a real `.env` with a fake secret — clean commit, exit 0. **This means the Claude-rendered dev-project hook is currently LESS safe than the Codex-rendered backstop hook for the identical 2 invariants.** Recommend `P080x-hook-fail-open-parity` (Tầng 1, Debate — touches security backstop) to port the fail-closed pattern from `crates/sos-install/src/templates/backstop-pre-commit.sh`'s embedded logic into `hooks/pre-commit`'s own `[6/8]`/`[7/8]` phases.
2. **A4 caveat (not a FAIL, narrow edge case):** on a brand-new zero-commit repo, `no-code-on-default.sh`'s `git show-ref --verify --quiet refs/heads/main` fails because the branch ref doesn't exist until the first commit lands, even though `git branch --show-current` already reports `main`. The gate's fallback hits the "cannot resolve default branch... allowing" warn-path and lets product code through on the very first commit only. Reproducible, pre-existing (not caused by dual-runtime), worth folding into the same P080x ticket or a lighter follow-up.
3. **A2-rev hook-winner is order-dependent (not a bug, but undocumented):** which render "wins" `hooks/pre-commit` depends on install order — Claude-first (`sos new` then `install --runtime codex`) leaves the dev `[8/8]` hook active (Codex declines to overwrite differing content); Codex-first (`install --runtime codex` then `sos adopt`) leaves the Codex backstop-minimal hook active (adopt stages the dev hook to `.sos-adopt-incoming/` for manual merge instead of overwriting). Both are correct non-clobber behavior, just asymmetric outcomes worth a one-line doc note somewhere (not urgent, no gap ticket needed on its own — folding the note into P080x is fine since that ticket is already touching the same file).
