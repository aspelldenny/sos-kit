## Worker CHALLENGE (Turn 1) → Chủ nhà APPROVE V1 — no objections

No Tầng-1 objections raised. One advisory note flagged pre-EXECUTE and carried through:

**Advisory (self-closing via oracle, non-blocking):** converting single-path `if`-checks into multi-path loops risks the classic bash pitfall `... | while read p; do ...; exit 2; done` — a PIPED `while` runs in a subshell, so `exit 2` there only exits the subshell, silently keeping the security hole open while still printing "BLOCKED" to stderr. **Confirmed relevant during implementation**: the initial implementation used `readarray -t ALL_PATHS <<< "$PATCH_PATHS"` (bash 4+), which failed with `readarray: command not found` (exit 127) on this dev machine's `bash 3.2.57` (macOS ships bash 3.2, never upgraded — `readarray`/`mapfile` are bash-4+ only). Fixed by populating the array via a herestring `while read` loop (`while IFS= read -r LINE; do ARR+=("$LINE"); done <<< "$VAR"` — no subshell, bash-3.2-compatible), then a plain `for` over the array for the actual block-if-any check. The plain `for` loop (not a pipe) means `exit 2` correctly propagates to the guard's exit code — the exact pitfall from the advisory note never materialized in the shipped code, and the negative-test below independently confirms this.

## Fixes shipped (`crates/sos-adapter-codex/src/templates.rs`, `crates/sos-adapter-codex/src/lib.rs`)

### #6 — multi-path bypass, SECURITY HOLE CLOSED

All 4 guards (`architect-guard.sh`, `orchestrator-guard.sh`, `block-env-edit.sh`, `approval-gate.sh`) changed from:
```
PATCH_PATH=$(... | grep -oE '...' | head -n1 | sed -E '...')
```
to extracting **every** path (`grep -oE` already emits one output line per match, even though every match sits on a single JSON input line — the phiếu's own insight, confirmed correct: no new regex needed, only deleting the `head -n1` stage), then looping with block-if-any semantics: ALLOW requires every extracted path to pass the guard's existing per-path rule; any single violating path → BLOCK. This inverts the old "first-path-exempt → allow-all" bug.

### #5 — approval bootstrap deadlock, fixed (two layers, coupled hard with #6)

1. **Self-bootstrap exemption** in `approval-gate.sh`: when `.sos-state/ticket-state.env` is missing, a patch touching the state file is allowed through ONLY if the entire non-ticket-file path set for that patch is exactly `{".sos-state/ticket-state.env"}` — one element, that exact value. Any additional path in the same patch is caught by #6's all-path extraction and falls through to the normal fail-CLOSED BLOCK.
2. **Install-time skeleton** — new 18th Asset `STATE_SKELETON` (`templates.rs`), target path `.sos-state/ticket-state.env`, content = empty `version=`/`approved_version=` skeleton. This is rendered via the existing `all_assets()`/`plan()`/`render()` path — **zero `sos-install::engine` change**. Non-clobber safety comes entirely from the engine's pre-existing generic checksum/manifest logic (`Decision::Conflict`: on-disk content differs from desired AND from the recorded manifest hash → never overwrite, stage instead) — once a real `approved_version=` is written by the workflow, that file's hash diverges from both the skeleton and the recorded baseline, so a later re-install can never clobber real approval state.

**Coupling note (per phiếu instruction, mandatory):** the #5 self-bootstrap exemption is safe ONLY because #6's all-path check lands in the same phiếu/patch. Without #6, an attacker could bundle `.sos-state/ticket-state.env` (satisfying the "missing state" bootstrap condition) with a second forbidden path (`.env`, `src/**`) in one `apply_patch`, and the old first-path-only guard would have let both through. With #6, the second path is caught by the all-path loop regardless of the bootstrap exemption — verified directly by test `approval_gate_blocks_bootstrap_when_state_file_plus_other_path`.

### #7 — spawn caveat, doc-only

Added one line to `agents_md()`'s existing orchestrator hard-rules list: spawning `architect`/`worker`/`advisory-watch`/`boundary-check` must either omit `agent_type` or spawn without a full-history fork — a full-history forked agent inherits the parent's `agent_type` (the exact P079 first-spawn failure). No hook/guard touched, pure prose addition; `AGENTS.md` stays well under the 32KiB limit.

## Known gap (documented, not guessed at)

`*** Move File: <src>` is paired with a separate `*** Move to: <dest>` line in the wider V4A apply_patch spec, but this was NOT present in the P078b3 ground-truth sample. This phiếu's regex still only matches `*** (Add|Update|Delete|Move) File: <path>` — the Move destination line is not extracted or checked by any guard. Per Luật chơi #6 ("KHÔNG guess format"), this is left as an open, documented gap rather than an invented fix. If Codex ever emits a `Move` with a `Move to:` line, only the source path is currently checked.
