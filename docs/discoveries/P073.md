## Assumptions in phiếu — WRONG (Tầng-2 self-adapt)

- **Anchor #2 (scripts count):** Architect stated 11 `scripts/*.sh`; actual count before P073 = 10 (the install-hooks + check-case-collision list was 11 names but one was double-counted). After adding `trust-gate.sh`, total = 11. Baseline covers 20 surfaces (5 non-script + 11 scripts + install.sh + phieu/phieu.sh + templates/setup-dev.sh). Self-adapted: noted in Discovery, not a Tầng-1 escalation.

- **`grep -P` unavailable for BSD grep** (macOS system grep). The initial `unicode_grep()` implementation used `[\x{200b}]` bracket class syntax which fails with `grep: invalid option -- P` when BSD grep is invoked from non-interactive bash. Also, the bracket class `[\x{200b}]` is invalid on macOS grep even when `-P` is present. Fix: switched to `LC_ALL=C grep -rn -e $'\xe2\x80\x8b'` (byte-pattern, portable — works on GNU grep AND BSD grep). No `-P` needed. Self-adapted (Tầng-2 implementation detail).

- **`grep -P` availability probe inside bash -c differs from interactive shell.** When the pre-commit hook is run as `bash scripts/trust-gate.sh`, the non-interactive PATH uses `/usr/bin/grep` (BSD, no `-P`). The `echo "" | grep -P ""` probe correctly returns false → falls to the byte-pattern fallback. Root cause documented in Discovery for future reference.

## Edge cases / limitations found

- **Tag range U+E0000+ (4-byte UTF-8) detection:** the byte-pattern approach used in the final implementation (`LC_ALL=C grep -e $'\x....'`) covers the 3-byte-encoded codepoints in the common hidden-unicode set. The tag range (U+E0000+, 4-byte) is listed in comments but not fully byte-enumerated in the pattern (would require listing ~128 4-byte sequences). In practice, text editors and LLMs rarely emit tag-range characters. Risk: LOW for sos-kit context. Mitigation: if a future phiếu needs tag-range coverage, install `rg` (ripgrep) — the script already probes for it first and ripgrep handles Unicode natively.

- **rg (ripgrep) not installed on this machine:** script probes `rg` first, falls back to byte-pattern `grep`. On machines with ripgrep the scan is more comprehensive (Unicode-aware, not byte-pattern-limited). Both paths tested locally; fallback confirmed working.

- **Non-breaking space U+00A0:** repo-wide scan returned 0 occurrences. Policy: U+00A0 in prose is allowed (it's visible to readers, used in some markdown tables). Not included in the gate's codepoint set.
