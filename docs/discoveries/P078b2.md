## Render/plan mechanism (exact)

- `crates/sos-adapter-codex/src/templates.rs` (NEW module) owns: 10 stable Asset-identity constants, `all_assets() -> Vec<Asset>` (fixed set), `target_path_for(identity) -> &'static str`, `content_for(identity) -> String` (pure `match` over identity, one function per surface — `agents_md()`, `agent_architect_toml()`, `agent_worker_toml()`, `agent_advisory_watch_toml()`, `agent_boundary_check_toml()`, `skill_md(name, description)`, `config_toml()`).
- `CodexAdapter::render()` (`lib.rs`) is now: `Artifact{ target_path: templates::target_path_for(&asset.identity), content: templates::content_for(&asset.identity) }` — pure, no fs I/O.
- `CodexAdapter::plan()` (`lib.rs`): `templates::all_assets().iter().map(|asset| { let artifact = self.render(asset, capabilities); ManagedOperation{ description: format!(...), target_path: artifact.target_path, content: artifact.content } }).collect()`.
- No filesystem read of `core/**` happens anywhere in this path — verified by code review (every `content_for` arm is a string literal/`format!` call, no `std::fs` in `templates.rs`). A CWD-mutating unit test to "prove" this mechanically was considered and rejected: `std::env::set_current_dir` is process-global and would race with other tests in the same binary under `cargo test`'s default parallelism (flaky by construction) — code-review citation used instead, per this report.
