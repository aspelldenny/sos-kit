## install.sh route A — before/after
**Before:** `fetch_bin()` assumed `repo == bin` name and installed straight to `$BIN_DIR/$bin`. No `sos` entry in `BINARIES`/`OPTIONAL_BINARIES`. Wrapper (`$BIN_DIR/sos`) was a 2-line bash dispatcher only.

**After:**
- `fetch_bin()` signature extended (`<bin> <required|optional> [repo] [dest-name]`, both new params optional/backward-compatible — all 10 existing call sites untouched, defaulted to `$bin`).
- New call: `fetch_bin "sos" required "sos-kit" "sos-bin"` — fetches from `aspelldenny/sos-kit`'s releases (repo name differs from binary name `sos`), installs to sidecar `$BIN_DIR/sos-bin` (NOT `$BIN_DIR/sos` — that path is reserved for the wrapper). Same fail-CLOSED integrity check as every other required binary (missing `.sha256` or hash mismatch → abort exit 1).
- Wrapper generation (`install.sh:153+`) now emits 2 extra lines before the `exec bash .../bin/sos.sh` line:
  ```sh
  : "${SOS_RUST_BIN:=$BIN_DIR/sos-bin}"
  export SOS_RUST_BIN
  ```
  `:=` never overrides an already-set value — a user's own `export SOS_RUST_BIN=/custom/sos` still wins (verified, see Nghiệm thu below).
- `bin/sos.sh` was NOT touched (route A per Debate Log Turn 2 — Architect ACCEPTed route A over route B specifically to avoid opening the P077e dispatch-contract surface).
