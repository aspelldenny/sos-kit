## OA-02 3-part fix — implementation summary (`map.rs`)

**Part 1 — Stack-aware source scanner.** Added `StackMarker` + `STACK_MARKERS` (5 entries: Rust/Python/Node/Go/Swift) and `detect_present_stacks()` — an unbounded-depth tree walk (excluding noise + kit-managed roots) that flags which stack manifest(s) are present ANYWHERE in the target, including nested monorepo sub-packages. For each present stack, `run()` additionally scans a generic extension-only surface (`path_substrs: &[]`, so it matches the extension ANYWHERE in the tree, not gated to a specific dir name) — this is deliberately broader than "just `src/`" so it also satisfies the monorepo/nested-package acceptance criterion without a second code path. Kept the pre-existing 6 dir-pattern surfaces byte-for-byte unchanged (Bash-parity for those retained).

**Part 2 — Exclude kit-managed assets.** Added `KIT_MANAGED_ROOTS = &["templates", "phieu", "scripts", "hooks", ".claude"]` + `is_kit_managed()` (checks only the FIRST relative-path component, not a substring match — avoids false-excluding e.g. a user's own dir that merely contains "scripts" as a substring). Wired into `scan_surface()`'s per-entry loop (applies to ALL surfaces, both pre-existing and new stack-aware ones) AND into `detect_present_stacks()` (so a manifest file accidentally living under a kit-managed root, e.g. a stray `Cargo.toml` inside `templates/`, doesn't spuriously trigger a stack). One mechanism, fires for both standalone `sos map` and map-within-adopt (since adopt just re-invokes the same binary).

**Part 3 — 3-verdict status.** `HEAD` const: `status: draft_needs_review` → `status: coverage_unknown`, plus an inline comment block documenting all 3 verdicts and their ownership (map only ever emits `COVERAGE_UNKNOWN`; `COVERAGE_REVIEWED` is human-set only, never asserted by the tool itself). `UNMAPPED_STUB` folded per O1.1 above. Both println confirmation lines updated to match.

**Exact 3-verdict field key/value chosen:** `status: coverage_unknown` (snake_case, matches existing YAML style) for both the normal-surfaces path and the zero-surface stub path. `PATH_VALID` and `COVERAGE_REVIEWED` are documented in the HEAD comment as the other 2 members of the verdict space but are never emitted by `sos map` itself (`PATH_VALID` is a property `doctor validate-map` computes at check-time, not a field map writes; `COVERAGE_REVIEWED` is a manual human upgrade).
