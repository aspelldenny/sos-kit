## Edge cases / limitations found

**Cargo compile-cache staleness on directory move (new finding, not anticipated in phiếu):** `cargo test --workspace` after the `git mv` initially FAILED — `sos-core`'s `dep_direction.rs` test panicked with `read_dir src: No such file or directory`, because a stale cached test binary from BEFORE the move still embedded the OLD absolute `CARGO_MANIFEST_DIR` path (baked in via `env!()` at compile time). Cargo's incremental-build fingerprinting tracks source-file content/mtime, not the crate's on-disk directory identity — since `dep_direction.rs`'s content didn't change, cargo reused the stale binary. Fixed via `cargo clean -p sos-core` to force a full rebuild. This is a one-time relocate cost, not a recurring issue (the embedded path is correct once rebuilt) — but worth flagging for any FUTURE crate-directory move: `cargo clean -p <crate>` after moving a crate that uses `env!("CARGO_MANIFEST_DIR")` or `include_str!`/`include_bytes!` with a stale cache present.
