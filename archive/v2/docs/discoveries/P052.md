## Implementation Notes

**Regex drift check:** `block-env-edit.sh` line 45 = `'^\.env($|\.)'`. `block-env-commit.sh` uses identical string. Zero drift between the two layers — feature, not debt.

**`.env.example` allowlist:** Exact basename equality `[ "$base" = ".env.example" ]` — mirrors `block-env-edit.sh:42`. No glob broadening.

**MERGE_HEAD guard:** `$(git rev-parse --git-dir)/MERGE_HEAD` — worktree/submodule safe (not hardcoded `.git/`). Identical to `no-code-on-default.sh:17`.

**No sos-kit self-opt-out:** Deliberate divergence from P050. The kit has no tracked `.env*` (anchor #5) — the gate is a near-no-op here by absence, not by opt-out.

**Task 4 (install-hooks.sh):** N/A — `core.hooksPath hooks` auto-picks up any executable script in `hooks/`. No registration needed.

## [O1.1] Resolution — `.envrc` Deliberately Excluded

`.envrc` (direnv config) is NOT matched by `^\.env($|\.)` — `rc` immediately follows `env` with no dot/end-of-string, so it exits no-match. This is a **feature, not a gap**:

1. `.envrc` is direnv config that is **committed on purpose** — it points at `.env` to load secrets; blocking it = false-positive.
2. Regex stays **verbatim with `block-env-edit.sh`** (P046) — one definition of "env file" at both edit-time and commit-time; the two layers cannot drift.

**Rule:** If `.envrc` coverage is ever genuinely needed, fix BOTH `block-env-edit.sh` AND `block-env-commit.sh` in one phiếu so the two layers stay in sync (one-disease-one-mechanism).

## Edge Cases / Limitations

- **Content scanning out of scope** — this gate is filename-only. Detecting API keys inside `config.json` or other arbitrary files is a `gitleaks`-class problem; explicitly deferred per phiếu scope question.
- **Windows msys2:** `basename` is POSIX-standard and available in msys2/Git-for-Windows bash. No Windows-specific issues expected.
- **For loop word-splitting on filenames with spaces:** the `for f in $STAGED` construct splits on whitespace. Filenames with spaces in `.env` paths would be mis-split. Low-likelihood for `.env*` files (not a common pattern) and matches P050's own `$STAGED` loop style — documented as a known limitation. A future hardening could use `while IFS= read -r` with process substitution.
