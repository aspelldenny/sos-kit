## Route chosen: (a) minimal pre-commit calling 2 embedded scripts — verbatim, single-source

Chosen per the phiếu's stated preference and Debate Log Turn 1's "no evidence route (a) is
broken." Route (b) (inline the 2 checks' logic directly into the Rust-embedded pre-commit string)
was rejected because it would duplicate `block-env-commit.sh`/`no-code-on-default.sh`'s logic in
two places (the standalone scripts AND a copy baked into the template), breaking the
single-source-of-truth property route (a) preserves — a bug fix to either guard script
automatically propagates to both the `sos new` dev-hook path and the `sos install` backstop path
without a second edit site.

## Dependency-closure oracle — how it works, why it closes the recursion

Prior fixtures in `crates/sos-install/tests/install.rs` each seeded exactly the piece the real
install was missing:
- P078f's hook-arming tests seeded hook file *content* directly into the synthetic `Plan` — never
  exercised the "install renders nothing" path (P078g's actual gap).
- P078g's `install_end_to_end_blocks_a_real_env_commit_after_fresh_install` seeded
  `scripts/block-env-commit.sh` directly into the fixture before running `apply()` — proving the
  ARMED hook chain blocks a real commit, but never proving the hook's OWN render output includes
  that script (round-4's actual gap).

P078i's new test `pristine_install_renders_closed_dependency_set_and_blocks_real_env_and_code_commits`
runs `engine::apply()` against a **git repo with zero pre-seeding** (`assert!(!root.join("hooks").exists())`
and `assert!(!root.join("scripts").exists())` before `apply()`), then:
1. Reads the rendered `hooks/pre-commit` content.
2. Extracts every `scripts/<name>.sh` substring reference via a manual scan (`extract_scripts_refs`
   — no regex dep in this crate's `Cargo.toml`, so this is a plain substring walk, not a full
   regex parser; sufficient because the assertion only needs candidate refs, not a general parser).
3. Asserts every extracted ref exists as a file among the SAME `apply()` call's own render output
   (`root.join(r).is_file()`).
4. Asserts the content never references `docs-gate`/`trust-gate`/`inv-gate`/`python`.

This closes the recursion mechanically: any future change that makes the backstop reference a
script it doesn't also render will fail this specific assertion, rather than silently passing a
fixture that happened to seed the missing piece.

A companion `pristine_install_backstop_fails_closed_when_guard_script_is_absent` test deletes a
just-rendered guard post-install and re-confirms the NEXT `.env` commit is still BLOCKED (not
silently allowed) — direct proof against the round-4 A3/A4 regression class.

Two smaller unit tests (`extract_scripts_refs_finds_both_backstop_dependencies`,
`backstop_template_does_not_reference_dev_only_tooling`) pin the template's exact reference set
and forbidden-token list independent of the full pristine-install flow, for faster failure
localization if either drifts.

This P078g-era test asserted `hooks/pre-commit`'s rendered bytes matched the kit-root dev hook —
