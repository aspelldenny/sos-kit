## Edge cases / limitations found

1. **`codex exec` requires `--sandbox workspace-write` explicitly** — default sandbox is read-only, and a run without this flag is vacuous (no writes attempted, hooks never exercised) — easy to mistake for a clean PASS when it's actually a no-op.
2. **Hook enforcement is trust-gated with a SILENT failure mode.** If the repo isn't marked trusted, Codex's PreToolUse hooks simply don't load — no error surfaces. A dogfood run against an untrusted repo will "leak" (block that should fire, doesn't) with no visible signal that the test was vacuous. Mandatory going forward: any Task-3-style verification must confirm the literal `"hook: PreToolUse ..."` line appears in output before trusting the PASS/FAIL call.
3. **`trusted_hash` is content-based**, not tied to a specific directory or install session — fixtures sharing the same rendered template can inherit trust from each other. Convenient, but means "trusted" is a property of file bytes, not of a reviewed instance.
4. E2 (Linux/Windows) is now a **deliberately deferred scope item** (Sếp decision 2026-07-23), not an unresolved gap — distinction matters for future audits of "why didn't P080 test Linux."
