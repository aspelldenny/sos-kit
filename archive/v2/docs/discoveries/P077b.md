## Dependency-direction gate — mechanism + negative-test proof

**Mechanism chosen:** cargo-native, two-layer (per Task 4 spec, no cargo-deny needed — confirms Anchor #6):
1. **Compiler graph** (structural primary) — `crates/sos-core/Cargo.toml` declares deps only on `{anyhow, serde, toml, chrono}` — zero `sos-*` crate dep.
2. **Guard test** (`crates/sos-core/tests/dep_direction.rs`) — recursively scans `sos-core/src/**/*.rs` for forbidden tokens `sos_adapter`/`sos_install`/`sos_hooks`/`sos_cli`, fails loud if found. Catches regression the compiler alone would miss (e.g. dep added to Cargo.toml but source not yet using it — the pure structural check only fires once `use` is written).

**Negative-test proof (ran, then reverted):**
```
$ echo -e '\n#[allow(unused_imports)]\nuse sos_adapter_claude;' >> crates/sos-core/src/state.rs
$ cargo build -p sos-core
error[E0432]: unresolved import `sos_adapter_claude`
   --> crates/sos-core/src/state.rs:120:5
    |
120 | use sos_adapter_claude;
    |     ^^^^^^^^^^^^^^^^^^ no external crate `sos_adapter_claude`
error: could not compile `sos-core` (lib) due to 1 previous error

$ git checkout -- crates/sos-core/src/state.rs   # reverted immediately
$ cargo build --workspace   # confirmed green again
```
This proves the one-way direction is enforced, not just asserted.

**cargo tree direction proof:**
- `cargo tree -p sos-core` → deps are `anyhow`/`chrono`/`serde`/`toml` only. Zero `sos-*` deps.
- `cargo tree -p sos-adapter-claude` → has `sos-core`, does NOT have `sos-cli`/`sos-install`/`sos-hooks`. Confirms adapter→core one-way.
